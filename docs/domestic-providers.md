# 国内语音通知：互亿无线与容联云

调研及离线实现核对日期：2026-09-27。两家均为真实 HTTP 协议适配，**尚未用真实账户或线路拨号验证**。注册、填写凭据、格式检查均不等于语音通知获准开通。本项目没有购买套餐或替用户申请平台认证。

## 配置与申请

在「设置 → 电话服务」选择对应平台；只在本机配置页填写凭据，不发到聊天、截图或 GitHub。首次真实测试先准备通知，再审核单次授权。后续自动通知必须另行明确启用。

| 平台 | 需要填写 | 开通边界 |
| --- | --- | --- |
| 互亿无线 | 语音通知 APIID、APIKEY、审核通过的模板 ID | 官方 FAQ 明确仅企业用户可开通，个人不可以；需要企业实名、场景及模板审核、额度和可用线路。 |
| 容联云 | 主账户 Account SID、Auth Token、App ID、服务商许可的通知文本 | 尚未确认个人能否获准语音通知；须先向平台确认主体、场景、文本与线路要求。不能承诺注册后即可拨号。 |

互亿入口：[语音通知文档](https://www.ihuyi.com/doc/voice/vm/api/Submit.html)、[开通及发送 FAQ](https://m.ihuyi.com/doc/voice/vm/faq_send.html)。容联入口：[语音通知文档](https://doc.yuntongxun.com/p/5a5342c73b8496dd00dce139)、[控制台](https://console.yuntongxun.com/)。费用以实际账户、套餐和服务商合同为准；真实呼叫及相关查询可能消耗额度，离线测试不联系服务商。

## 互亿模板与协议

- 本版本只发送中国大陆 `+86` 手机，转换为 11 位国内号码。每次只提交一个收件人。
- 模板需按顺序包含两个变量：任务标签、事件状态。变量内容固定为 `AI任务|报告完成` 等；实际模板正文及变量位置必须由服务商审核。模板 ID 不预设，不借用验证码模板。
- 状态取值为「报告完成、执行失败、等待处理、重试耗尽、需要您决定、本轮结束」。报告完成不等于通过验收。不会上传任务摘要、问题、文件名、代码或电话回复选项。
- 固定 HTTPS POST `https://api.ihuyi.com/vm/Submit.json`，UTF-8 表单字段 `account/password/mobile/content/templateid/time`。动态密码按官方通知文档使用 `MD5(APIID + APIKEY + mobile + content + Unix秒时间戳)`；不传 APIKEY 明文，不把签名放入 URL。
- 只有 `code=2` 且返回有效 `voiceid` 才记为「已受理」。受理不等于接通。官方推送文档没有可核实的密码学验签字段，本项目不开放该回调，也不把来路不明的回执视为完成。请到控制台核对最终结果；引擎有界等待后标记「结果不确定」，不重拨。

来源：[语音通知提交接口及动态密码](https://www.ihuyi.com/doc/voice/vm/api/Submit.html)、[模板规范](https://www.ihuyi.com/doc/voice/vm/template_specification.html)、[状态报告推送](https://www.ihuyi.com/doc/voice/vm/api/PushReport.html)。

## 容联文本、签名与查询

- 使用「语音通知」的 `LandingCalls`，不使用语音验证码接口。本版本只接受中国大陆 `+86` 手机，发送国内 11 位号码。
- 通知文本默认空，必须填写已获服务商许可的文本，最多 500 字符，只允许 `{status}` 变量，例如自行获批的任务状态提醒。示例语义不代表平台已经审核。Agent 自由摘要不会替换进文本。
- 固定 HTTPS POST `https://app.cloopen.com:8883/2013-12-26/Accounts/{accountSid}/Calls/LandingCalls`。JSON 包含 `appId/to/mediaTxt/playTimes`，只播放一次；不设置自定义显号、录音地址或未经验证的回调。
- URL 的 `sig` 为大写 `MD5(accountSid + authToken + yyyyMMddHHmmss)`，Authorization 为 `Base64(accountSid + ':' + 同一时间戳)`。时间戳按本机时间生成，请保持系统时间准确。认证依据主账户 REST 签名文档，密钥不写日志。
- `statusCode="000000"` 且返回有效的 32 位 `LandingCall.callSid` 才记「已受理」。受理 90 秒后，使用同样签名执行 GET `/2013-12-26/Accounts/{accountSid}/CallResult?sig=...&callsid=...`；不再次发送呼叫。官方查询状态 `0` 对应成功，`1/2` 对应未接听/失败，但字段没有明确区分通话中与已结束。本版本仅将结果作为提示，保持占用通话槽直至引擎截止，之后标「结果不确定」、到控制台核对。
- 查询结果成功只说明服务商报告呼叫成功，不能证明已经结束、用户听完整段或用户验收任务。不能把这些有限字段冒充可靠结束回执。

来源：[语音通知 LandingCalls](https://doc.yuntongxun.com/p/5a5342c73b8496dd00dce139)、[REST 地址与认证](https://doc.yuntongxun.com/p/5a533ac73b8496dd00dce025)、[CallResult 查询](https://doc.yuntongxun.com/p/5a5342c93b8496dd00dce141)。

## 安全与实际验证状态

已实现并在本地替代 HTTP 响应验证：精确端点及字段、两套签名、固定事件映射、配置缺失及号码拒绝、禁止跳转、10 秒超时、撤授权信号中断、响应大小限制、错误脱敏、明确拒绝与受理不明的区分、容联签名查询。所有请求均由测试内存函数截获，未使用真实号码、密钥或付费 API；这不等同真实线路验证。

每次提交只有一次 HTTP 请求，无 SDK 自动重试。网络错误、超时、5xx、跳转、无法解析、成功但缺少呼叫 ID 都保守记为「结果不确定」，不自动重拨；服务商明确拒绝也不重拨。停止后续通知会取消尚在等待的请求，但**中断 HTTP 不保证运营商取消已受理呼叫**。两家适配都没有已验证的远程挂断，短语音可能继续播放。

手机接通、线路审核、计费、中文实际效果须用户取得对应账户权限后，在界面明确授权单次测试，再对照手机和服务商控制台核验。两家当前均不支持电话双向回复、SIP 或模拟座机硬件；已有独立 SIP 通道不代表这两家接口支持这些功能。所有实现根据公开协议独立编写，未复制授权不明的示例代码。
